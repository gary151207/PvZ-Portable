# 植物与特殊卡片编号分离

## 决策

`SeedType` 只包含连续编号的植物。魅惑大喷菇为 `63`，毒液豌豆为 `64`，下一株植物直接追加为 `65`；新增植物时同步追加 `gPlantDefs`，无需移动特殊卡片。洗牌按钮等 21 种非植物卡片使用独立的 `SpecialPacketType`，编号保持 `64–84`。可容纳两类卡片的种子包、光标、老虎机下一张卡和可拾取卡片使用 `PacketType`，其类别为 `NONE`、`PLANT` 或 `SPECIAL`。

`.v4` 新文件的头部版本为 `2`。原有整数 ID 保留，并在卡片对应的 TLV 对象中写入类别字段：种子包 `101`（当前卡）和 `102`（老虎机下一张卡），光标 `101`，金币 `101`。版本 `2` 可同时表示植物 `64` 和特殊卡片 `64`。

游戏直接读取头部版本 `1` 时，按合并前已提交的魅惑大喷菇版本解释：植物 `0–63`，特殊卡片 `65–85`。该版本缺少编号体系标识，无法可靠识别更早存档。对特殊卡片使用 `64–84` 的更早版本，先显式执行：

```bash
python3 scripts/pvzp-v4-converter.py migrate-packet-ids --legacy-special-base 64 old.v4 converted.v4
```

命令保留原文件，将种子包、光标和可拾取卡片的 ID 转为带类别的版本 `2`。独立毒液豌豆开发分支中植物同样使用 `63` 的实验存档不自动兼容。

读取时还会校验动画帧范围。实验分支存档中的毒液豌豆 `63` 及其动画编号会被误认为魅惑大喷菇；若帧范围与当前动画定义不符，游戏将拒绝加载，把原文件改名加上 `.incompatible` 后开始新关卡，避免绘制越界崩溃。
